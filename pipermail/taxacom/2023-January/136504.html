Thanks Doug and Adam for the latest comments. In my list I (and colleagues)
will generally not use abbreviations. As this article is purely digital
(and open access) there are no space constraints.

With respect to the definition (thanks) that "*synonym*, *n*. Each of two
or more names of the same rank used to denote the same taxonomic taxon." -
would I be correct to understand from this that an infrasubspecific name
such as an aberration cannot be considered a synonym?

With respect to:

Article 45.6.4. it is subspecific if first published before 1961 and its
author expressly used one of the terms ``variety" or "form" (including use
of the terms "var.", "forma", "v." and "f."), unless its author also
expressly gave it infrasubspecific rank, or the content of the work
unambiguously reveals that the name was proposed for an infrasubspecific
entity, in which case it is infrasubspecific (our emphasis).

I take that to mean that subspecific names (or inferred before 1961 by var
forma v and f) are considered to have the same rank as species and
therefore qualify as synonyms?

Sorry to gnaw over these details. Neve would have made a lawyer.

John

> 'unavailable'?
>
> All relevant names can be included in a taxon synonymy, and it is useful
> to add the status of the name after it as well. I use '[IFS]' for
> infrasubspecific names, and similarly it is worth including other types
> of status too, eg. JOS (junior objective synonym), JS (junior synonym),
> JH (junior homonym), NN (nomen nudum), PS (published in synonymy) etc.
> Note that a JOS is an unavailable name, since it is based on the same
> individual type specimen (species-group), or the same type species
> (genus group); whereas a JS is a subjective opinion, and the name is
> still available.
> Don't forget to include a list of abbreviations. I recommend NOT using
> 'NP' for homonyms as nomen praeoccupatum, and nomen protectum are
> different but have the same initials.
>
> > This question arises as I finalize a revised Hepialidae catalog, and had
> > followed Nielsen et al in listing infrasubspecies name. In the current
> list
> > I include information on type locality and type depository only for
> species
> > and subspecies names (when known). For infrasubspecies names I have just
> > noted the locality (i.e. not as a type locality), and collection
> depository
> > (but, again, not as a type collection).
