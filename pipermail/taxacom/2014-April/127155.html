> To chime in here one more time --
>
> I again agree with Stephen and I think Doug is not interpreting things in
> a "broad" sense to be inclusive of available names, but rather he is being
> dangerously* "restrictive". The ICZN has had a history of being
> broad-minded and not censoring the actions of zoologists when attempting
> to name species. It has even allowed the specimen upon which a photograph
> was based to be a primary type; and the same for the specimen behind an
> illustration (although with the latter there are confounding cases that
> have had an illustration based on more than one specimen!). The only
> difference between a depiction of a specimen and a database record is that
> the physical depiction (photo or illustration) can be verified by a third
> party. If you want to re-write the Code and be more clear, then THAT is
> the wording you need to put in Article 16 to restrict future uses of
> database "specimens" as primary types. But as the Code is currently
> written, Hoser did all that was required, because the Code does not say a
> specimen has to be "verified" that it is need the specimen an author said
> it is.
>
> So -- again: in this case, there is indeed a specimen upon which a
> database entry was made (whether it be a physical specimen or an
> observation). It was not fantasy, and it WAS verified by the collector(s)
> listed in the database. Someone again is obfuscating this thread
> discussion by inserting the word "unverified" when what was said by the
> FLMNH database manager about those "occurrence" records was that they were
> "unvouchered" [= not present in the collection].
>
> Doug had said earlier in this thread (in a response to one of my posts)
> that in his opinion these observations were like the Xmas bird count. To
> keep with that analogy, then indeed these would be verified
> identifications since the Xmas bird count has some pretty strict rules on
> IDs of sightings. Sure there are abuses of verifications of sightings --
> as there are abuses in taxonomy in general. For example: how many
> "holotypes" have been described that have been said in the work to be
> deposited in a particular collection, but they have never found there or
> in nature? When that happens, the name is said to be either a nomen dubium
> or incertae sedis. In this situation, the only difference from Hoser's is
> that Hoser's species DOES occur in nature!
>
> But to get back to the crux of the matter. Some on the list want to nix
> what Hoser has done because they claim the specimen (with a specimen
> number) that he specifically designated "did not exist". That is hogwash.
> And is bordering on censorship, in my opinion.
>
> *I do not at all condone Hoser's m.o. But to avoid being labeled as
> censoring a worker's intention to describe a new species according to the
> Code, we have to be careful and a bit more 'broad-mined' until someone
> comes along and re-writes the Code to avoid this from ever happening again.
>
> -Neal

> >We are at the crux of the problem now. Doug suggests that I think that
> >anything that the Code doesn't explicitly prohibit is therefore allowed,
> >but it is not that simple! In this case, the Code requires that a
> >holotype be designated. But there is no definition in the Code to specify
> >or constrain how exactly a holotype may be designated. At a minimum, a
> >unique specimen must be somehow specified (pointed to). Stating something
> >equivalent to "the specimen observed in the wild on DATE and TIME by
> >OBSERVER and recorded in DATABASE" therefore may specify a unique
> >specimen. Doug is perhaps confusing this with indication, as defined by
> >the Code. This has nothing to do with the designation of holotypes, but
> >indication is an alternative to description/diagnosis, whereby indicated
> >diagnostic information (including illustrations) must be in the published
> >literature. Hence, Doug highlights that a database record is unpublished.
> >But Hoser is not using the database
> > record to indicate diagnostic characters, he is simply usintg it to
> >point to a unique specimen to act as a holotype. At any rate, whatever
> >the opinion of individual commissioners is on this case is irrelevant, as
> >only an officially *published* Opinion by the ICZN can overturn the prima
> >facie availability of Hoser's names in this case.

> >Finally. At least ONE person here interprets the Code the way the
> >Commissioners do. Explicit fixation means there can be no ambiguity as
> >to which specimen is the holotype; the only - I repeat, ONLY - provision
> >in the Code that allows for the holotype to be something other than a
> >physical specimen is Art. 73.1.4, which permits authors to explicitly
> >designate illustrations as types. After 2000, THERE ARE NO OTHER ALLOWED
> >EXCEPTIONS. Mr. Thorpe seems to be under the mistaken impression that
> >anything which is not explicitly prohibited (i.e., that the Code does
> >not explicitly say "unpublished observations cannot be used as the basis
> >for a holotype designation") must therefore be allowed, but that is NOT
> >how this works. A database record is UNPUBLISHED, and cannot therefore
> >be cited as a method of indication for a type specimen. Everything in
> >the Code assumes that the relevant bits of information are PUBLISHED.
> >Again, if Hoser had published photos of the type specimens, the Code
> >would - marginally - have been satisfied, so long as he explicitly
> >designated those photos AS the types (under 73.1.4). To reinforce my
> >point, there is ONLY ONE Article in the Code that allows for the use of
> >unpublished data relevant to type designation, and that is Art.
> >72.4.1.1, which allows for unpublished information to be used in the
> >determination as to which specimens are part of the type series - but
> >this is explicitly ONLY for names published prior to 2000!! Hoser's
> >names were published AFTER that cutoff, and are therefore NOT eligible
> >to make use of unpublished data when determining which specimens are in
> >the type series - accordingly, there is no type series in this case,
> >because there is no holotype.
> >
> >There are no other if's, and's, or but's to be applied in this case,
> >despite what Stephen, Neal, and others are trying to claim; Hoser failed
> >to meet the conditions for an *explicit fixation* of a holotype, as
> >required by Art. 16.4.1, therefore his names are unavailable. It might
> >have worked prior to 2000, but the present edition of the Code,
> >mercifully, contains provisions that exclude the present case.
