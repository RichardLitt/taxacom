 Thomas wrote: What makes it so difficult is that nomenclature and taxonomy
overlap in one crucial point: the name-bearing type.

I think you could tease this out. That meta data that is important for
knowing you have the type be deemed nomenclatural data, ie museum number,
which museum, type locality, collection date, collector, possibly a few
others that can be discussed and may differ a little between some groups of
taxa. Declare these (in the code) as nomenclatural data and hence it must
be preserved with the nomenclatural act, ie published, archived and
registered. To be fair in many descriptions this is effectively already
done just not stated as such.

Everything else about the type is taxonomic data and hence can be discussed
as needed per the taxonomic reviews using it. The most important thing is
to be able to identify the type and I am not meaning to some taxa, I am
meaning identify it is the type for a particular name. It is hence the
owner of that name so the info required nomenclaturally is the
identification of the type. Info needed to stick it in a tree and decide
who its related to is all taxonomic.

Cheers Scott

>  Nevertheless, the bigger issue is whether a name unavailable on a
> technicality should still be used as if it were available, in the absence
> of an alternative name. I say yes. One reason is that many names which are
> being used are actually unavailable on unnoticed technicalities* (e.g. lack
> of a specified archive for the journal record used for ZooBank
> preregistration, something which is very rarely checked properly). So, we
> just use names and, if the are unavailable on a technicality, we just leave
> it to other people to sort out (the few people who pay that much attention
> to nomenclature). Then, if the problem gets sorted out sensibly, we can
> simply continue to use the name as if nothing had happened. But then, why
> bother "fixing" the problem if it makes no difference to usage anyway? At
> any rate, the code should be rewritten so that there are very few ways that
> names can fail to be available by mistake and it is obvious when it happens.
> Again, a requirement to upload treatments of new taxa to an online archive
> might be the best approach, so that a successfully uploaded treatment by
> definition makes the name available (apart from in cases of deliberate
> fraud), independently of publication elsewhere.
> The only reason why a name should be considered to be unavailable is if
> there is some actual problem in applying the name to a species. Remember
> that there is no actual requirement to archive, only to specify an archive.
> Therefore, the fact that supplementary appendices cannot be adequately
> archived is not a real problem, since the main part of the work might not
> get archived anyway! If the treatment does vanish, never having been
> archived, *then* the name can be deemed unavailable, but there is no point
> considering it to be unavailable just because it *might* vanish in future.
> *A good example where availability is messy is Mnesarchella dugdalei
> Gibbs, 2019. The author forgot to specify the type repository in the
> treatment itself (p. 55, something only I have seemed to notice!), but, in
> an appendix (p. 64), they list material with the primary type written in
> bold with a specified repository (NZAC). My opinion is that this appendix
> listing saves the day, even though it is remote from the treatment, within
> the same work.
> Stephen

> Supplementary Materials associated with scientific publications issued
> electronically is a highly relevant issue, and I was surprised to read the
> disclaimer. Note that the journal has Author Guidelines including how to
> propose new nominal taxa, but this part of their guidelines has probably
> not been peer reviewed by a person well-versed in zoological nomenclature.
>
> The ICZN is currently going through the Code, sentence by sentence, in
> order to provide an extensively updated proposal for a fifth edition, which
> will be disseminated widely for a one-year public review period. This
> cannot be done fast, but we make progress and will hopefully have something
> to present in a year's time from now.
>
> The issue of Supplementary Materials will be discussed within the
> Commission in the near future, and I trust that we will come to a decision
> on (1) how to interpret Supplementary Materials under the current Code, and
> (2) what to propose for the next edition of the Code.
>
> There are several issues involved under (1), including whether or not
> supplementary files are part of the 'work' (note that also traditional
> paper-based books can be "issued in parts").
> In the present case, the file providing the description, type fixation,
> and type depository is a Word file, which unambiguously is *not* acceptable
> for being considered as published in the sense of zoological nomenclature.
>
> I should like to cite (once again), from the Introduction to our current
> Code from 1999, where W.D.L. Ride anticipated that ?new information
> systems? would become a challenge to how we disseminate nomenclatural data
> and establish nomenclatural availability, and he suggested that ?the
> solution will not lie in patching up a definition of publication but,
> rather, in scrapping it and finding a means of replacing ?publication? as a
> primary determinant of availability?.
>
> Amazing foresight!
