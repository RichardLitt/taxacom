On 2/6/23 15:21, Francisco Welter-Schultes via Taxacom wrote:

> My understanding of Art. 11.7.1.1 is that Gorgonopsidae contains the 
> stem, so it would formed in agreement with that regulation. Thanks 
> Laurent for pointing this out, we should clarify this in Code-5. 
> Should read "was formed in accordance with Art. 29".
Interestingly, the conflicting provisions (11.7.1.1 requiring to use the 
stem of the type genus name, vs. 29.1 "allowing" the use of the entire 
name) both result from changes introduced in Code 4. In Code 3, a 
family-group name had to be "based on the generic name then used as 
valid for a genus contained in that family-group taxon" (no reference to 
the stem of that name), and Art. 29.1 did not exist -- a name formed 
from an entire generic name instead of its stem was incorrectly spelled, 
and had to be corrected.

I still do not see that Art. 29.1 serves any actual purpose given the 
existence of 29.4 and 29.5 -- if it was just me, I would simply delete it.

> And this means, no matter if the Code regards a spelling Gorgonopsidae

> correct a spelling based on an incorrect formation in the original 
> publication. So the original spelling must not be corrected.

This is a possible reading of the current text... But it means that a 
typo in the stem used in a new family-group name would be correctable 
only if it can be linked to an existing incorrect spelling of the type 
genus. So what would you do to cases like "Prachyptilinae" proposed for 
Pachyptila; "Struthiididae" proposed for Struthidea; "Pelagodornithidae" 
for Pelagornis ? Are these correct original spellings unless another 
spelling is in prevailing use ? Or are the names unavailable from the 
sources where they were so spelled ?

In Code 3, any violation of a provision of Articles 27 to 31 in the 
formation of a name was an incorrect original spelling, and its 
correction was mandatory. This included dedicated species-group names, 
as well as any incorrectly formed stem in a family-group name. It has 
always been obvious that these had ceased to have to be corrected in 
Code 4 only as a result of editorial sloppiness. (For reasons I have 
explained elsewhere, e.g. here : 
https://nam10.safelinks.protection.outlook.com/?url=http%3A%2F%2Flist.afriherp.org%2Fmailman%2Fprivate%2Ficzn-list%2F2015-June%2F013522.html&data=05%7C01%7Ctaxacom%40lists.ku.edu%7Cd3ee461ca2264dc9b88e08db08e46854%7C3c176536afe643f5b96636feabbe3c1a%7C0%7C0%7C638113549321362877%7CUnknown%7CTWFpbGZsb3d8eyJWIjoiMC4wLjAwMDAiLCJQIjoiV2luMzIiLCJBTiI6Ik1haWwiLCJXVCI6Mn0%3D%7C3000%7C%7C%7C&sdata=Ij1xvfnFNtdW3NQrhFlVkDgp8gBuL92xBtXQfVzNzNA%3D&reserved=0 
.) This reflected a long-standing historical practice; it was changed 
for no clear reasons; it resulted in the Code being inconsistent; and a 
significant portion of the community has since continued to act as if it 
had not been changed anyway.

I would revert to this, not try to reinvent the wheel.
